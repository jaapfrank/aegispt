## Proposed change

Three options, all separately filed:

1. **Capability-extension (preferred when Claude credits return)** — none. Smoke 27 (Claude) shows the system CAN solve XBEN-002 when the picker hypothesis-quality is high enough. Wait for credits.

2. **OAuth prompt tuning** — extend the picker user_content envelope to BIAS toward the CPG-surfaced access-check predicates (`or_(creator==user, archiver==user)` etc.) when the source-aware pipeline has produced them. gpt-5.5 reads these but doesn't weight them as heavily as Claude. Make them STRUCTURED hints not just narrative text.

3. **Critic-loop extension** — when an exec_plan completes with no flag literal in any response body and CPG has surfaced sinks, fire script_critic on the exec_plan transcript (currently the critic only fires on failed code-exec-attack tasks). This would feed the missed-chain back into a revision attempt without needing a fresh picker round.

Picked option to defer: 1 (least work, highest expected value when credits return). 2 and 3 are upgrades worth doing regardless, but they trade off OAuth-specific prompting against Claude-specific prompting and would benefit from an A/B harness measurement first.
