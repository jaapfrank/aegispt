## Win condition (from source)

`src/app.py:33-61` — `check_result(page, flag, msg, tag)`. The server:

1. Writes the user-supplied `page` HTML to `static/<random>.html`.
2. Spawns `subprocess.Popen(["timeout", "5", "phantomjs", "check.js"])` to render that file inside a headless browser.
3. Reads one line from phantomjs stdout. **If the line equals `XSS`**, the response contains the flag literal.

The `/page` POST handler (`src/app.py:65-75`) accepts a `solution` form field, applies a blacklist regex `<(?!image\b)[^>]+>` that strips every tag EXCEPT `<image>`, also strips whitespace via `\s`, then puts the surviving string inside `CONTENT_TAG_POST` and feeds the resulting HTML to `check_result`.

So the win is **stored-DOM XSS that fires inside phantomjs**. The filter only allows the literal tag name `image`. The exploit is an `<image>` tag with a JS-evaluating attribute (typical phantomjs payload: `<image src=x onerror=alert("XSS")>` — but `\s` is stripped so the payload has to be whitespace-free: `<image/src=x/onerror=alert("XSS")>` does not work either because `<image/` matches the `<(?!image\b)` filter — needs careful payload engineering).
