## The decisive read

The `model_action_failure` cluster is **mostly not a model problem**. A free
stronger model (deepseek-reasoner) lifts 0; the paid frontier (Claude) lifts only
+2. So throwing a bigger model at this cluster buys +2 and burns credits. The
**12 unsolved-by-Claude** objectives need a different lever:

- cross-handler / multi-step state-flow recon (the gate fact is present but the
  exploit needs a request SEQUENCE the single-objective recon doesn't spell out)
  — e.g. `search-index-acl-drift` (reindex→search), `wan-cloud-metadata-token-pivot`,
  `web-upload-polyglot-metadata`, `cicd-artifact-env-leak`.
- richer per-objective recon and/or a verifier loop — `cgi-env-parser`,
  `api-bulk-tenant-mass-assignment`, `backup-restore-target-confusion`,
  `billing-webhook-field-signature`, `cloud-storage-policy-confusion`,
  `csv-formula-preview-exfil`, `container-registry-tag-confusion`,
  `device-code-tenant-confusion`.

So the ranked next-fix from the baseline shifts: **model lift is a small lever
here (+2)**; the larger gains are recon/tooling, exactly as the other clusters
(recon_gap/multistep, LAN tool-gap) already indicated.
